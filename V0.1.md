# V0.1 — what is proven, what is debt

Audited 2026-08-09 against `BOOTSTRAP.md` §Definition of done. Every claim here
names the test, bench or workload that backs it; anything not backed that way is
in the debt section instead.

**The headline number: Ehkatra reproduces real Excel on 74.2% of 1,366
oracle-captured cases** under `Profile::Compat` (W-ORACLE). That figure is
measured against Excel 16.0 build 20228 over COM, not against documentation, and
the 25.8% that fails is enumerated by cause and case count in
`docs/44-debt-register.md`.

## 2. Gates

`pwsh -File tools/gates.ps1` — all green:

```
fmt · clippy -D warnings · 323 tests · no_std wasm32 kernel build
dep budget 1/5 kernel direct · 10/12 kernel closure · 29/40 workspace
supply chain: advisories ok, bans ok, licenses ok, sources ok
differential replay: oplog c79fa533… state b58d5505… — native == wasm32
kernel purity · host isolation · loopback-only listeners
```

**A caveat about how that line was produced.** `tools/gates.ps1` requires
PowerShell 7; on a host with only Windows PowerShell 5.1 it aborts in the clippy
step, because 5.1 wraps a native command's stderr in an `ErrorRecord` and cargo
writes its progress there — a green build is reported as `NativeCommandError`.
The re-verification behind this audit therefore ran each gate **individually**,
not through the one-command script the solo model asks for. The gates are green;
the *one command* is not currently one command on every host. Filed as **TD-47**.

The dependency budget is the one worth pausing on: **29 of 40**, and nineteen of
those twenty-nine are `rusqlite` (D-073). Everything written this quarter —
JSON, CSV, ZIP, DEFLATE, XML, XLSX, MCP — added **zero**.

## 3. Measured

Full detail and machine context in `MEASUREMENTS.md`. Re-run in full for this
audit, because docs/38 makes a stale number a release blocker.

| Workload | Result | Against |
|---|---|---|
| **W-ORACLE** | **74.2%** (1,014 / 1,366) | the published compatibility number |
| W-TILE-10M | 8.43 B/cell import · 11.09 collab · 1.0× promotion amplification · 123.6 MB | A-001 400 MB — **pass** |
| W-CHAIN-100K | 114.0 ms full · 0.618 ms incremental | 200 ms / 8 ms — **pass** |
| W-SYNC-RELAY (50 replicas) | p95 3,700 bus-ms · converge 2,140 **bus-ms** (6.8 min wall) · all hash-equal · 45/45 queued ops delivered across a mid-run kill | **pass** |
| W-OPEN-1M | cold open 7.86 s · **salvage loses nothing** · container 307 MB | see TD-45 |
| W-XLSX-CORPUS | 19/20 files at 100% part coverage · 17/20 lossless | starter corpus |
| W-REPLAY-5K | native == wasm32, bit-identical | DP-A2 — **pass** |

**Read the sync row's unit carefully.** Propagation and convergence are in
**bus milliseconds** — the deterministic transport's simulated clock, one hop =
5 ms — because they are protocol properties, round trips needed to reach every
replica, not properties of the host (docs/38). Converting 2,140 bus-ms into
"2.14 s" states a wall-clock duration the run never had: its wall time was
6.8 minutes. Quote the two numbers with their units or quote neither.

Three of these moved during the audit and all three are explained in
MEASUREMENTS.md rather than restated: **W-ORACLE** rose 65.6% → 71.4% → 74.2%
across the two cancellation mechanisms and the cheap docs/50 §7 fixes;
**W-CHAIN-100K** regressed 23% (TD-44); and **W-OPEN-1M**'s *workload changed*
because the old harness measured a container shape TD-30 has made unreachable.

docs/38 §39 makes the regression a filing, not a footnote: >5% p95 motion on any
W-* workload against the last release requires a signed-off debt entry. TD-44 is
that entry, and it is listed in §6 rather than left to this table.

## 4. The two demos BOOTSTRAP asks for

**Two replicas through a real relay**, `demo/collab.ps1` — loopback 7423, 13 + 6
concurrent edits including a row inserted into the span another replica is
writing:

```
peer 1: 13 local edits applied, 0 refused    peer 2: 6 local edits applied, 0 refused
STATE HASH 1: 2f51c7f3c193b490…              STATE HASH 2: 2f51c7f3c193b490…
DEMO PASS -- both replicas converged
```

**An MCP client completing describe → preview → apply → undo**, driven by hand
through the stdio binary:

| # | call | result |
|---|---|---|
| 2 | `apply_edits` A1=10, A2=32 | `applied 2`, `rows_added 2`, version `8c699e03…` |
| 3 | `describe_workbook` | 2 rows × 1 column, 2 cells filled |
| 4 | `describe_sheet` | per-column stats, sample rows |
| 5 | `preview_edits` B1 `=A1+A2` | `preview_hash c0cdb2da…`, impact reported |
| 6 | `apply_edits` B1 `=A1+A2` | version **`c0cdb2da…`** |

The detail worth noticing: **the `preview_hash` from step 5 is exactly the state

workbook that would exist. And stderr was empty throughout — nothing but
protocol reaches stdout.

## 5. What is *not* in v0.1

Named because omissions inflate confidence. BOOTSTRAP excludes these by design:
UI and rendering · charts · pivots · styles beyond number format · comments ·
merged cells · auth beyond a bearer token · server persistence beyond local
files · E2EE · i18n beyond UTF-8 · **XLSX write**.

Added to that list by decisions taken this quarter:
* **The MCP `query` SQL tool** (D-095, TD-42).
* **Dates as a type** — they are serials with a number-format code (D-043,
  TD-40).
* **The 1904 date system** — the 1904 oracle corpus scores 20.0% and the number
  is published at full size rather than folded into the headline.

## 6. Debt, ranked by what it costs

The register has **38 live entries and 9 paid** — TD-01 through TD-47 with no
gaps, less the nine struck through. (The previous draft of this section said 36
live; the count was taken by hand and was wrong. TD-24 is filed as *largely*
paid and counted with the paid; TD-14 appears struck through a second time in
the oracle cross-listing, where the strike means "already filed above", not
paid.) These are the entries that would change a decision:

**Compatibility — the 25.8% of W-ORACLE that fails, by measured case count:**

| | Cases | |
|---|---:|---|
| TD-33 | ~98 (+104 in 1904) | Date semantics: Excel's self-contradicting 1900 calendar, `DATE`'s year<1900 rule, no 1904 system. **The largest single cluster** |
| TD-36 | ~28 | `TEXT()` unimplemented |
| TD-14 | ~24 | Approximate-match lookup — a deliberate v0.1 refusal, now measured |
| TD-34 | ~20 | The `COUNTIF`/`SUMIF` criteria sub-language |
| TD-32 | ~14 | `compat_parse_15` — Excel truncates numeric literals at parse time |
| TD-35 | ~6 | `SEARCH`/`FIND` wildcards |

**Structural — things that change what the product can promise:**

* **TD-45 / TD-31 / TD-24-residual — one change, three entries.** A v0.1
  snapshot body *is* the compacted op set, so opening replays it and three
  retained snapshots cost three copies. The tile-image body closes all three.
  This is the highest-leverage piece of work outstanding.
  **Status (session 17):** the image is built, tested and fuzz-clean
  (`usk_state::image`), and is *not* wired in. Adopting an image and applying a
  tail loses the identity of a retained loser at any cell first written inside
  the image — which ADR-006 and DP-A8 promise to keep and BOOTSTRAP lists as
  differentiator 3. Resolving that is **TD-46**, and it is a decision about
  ADR-005's memory bar before it is code.
* **TD-37 — the import sandbox has no syscall filter.** Address-space
  isolation, memory and process caps, wall clock, fresh process: all enforced.
  "No network" is *structural* (the parser links none) rather than enforced,
  because Windows offers no seccomp equivalent without elevation. Matters most
  before any server-side import fleet.
* **TD-44 — W-CHAIN-100K is a signed regression, not a passing number.** Full
  recalc 92.6 → 114.0 ms (+23%) and incremental 0.328 → 0.618 ms (+88%) when the
  compat cancellation rule landed. Both still clear their budgets, which is why
  the table says *pass* — but docs/38 §39's >5% rule makes the entry mandatory
  regardless, and a budget cleared by a shrinking margin is worth seeing.
* **TD-39 — XLSX read models values, formulas and number formats only.** Charts,
  drawings, pivot tables, themes, tables, conditional formatting, data
  validation, defined names, merged cells and column widths read as *nothing*.
  Measured rather than guessed: `part_coverage` puts `14-unmodelled-parts.xlsx`
  at 50% and names every dropped part. Bounded today because XLSX write is out
  of scope; it becomes a round-trip obligation the moment write lands (TD-04).
* **TD-28 — the work is uncommitted, and CI has never run.** Two facts, and the
  first is the one a reader will not guess. `HEAD` is at Rows 10–11; **45 paths
  in the working tree are uncommitted, and the crates delivering Rows 12–15 are
  untracked** — `usk-csv`, `usk-json`, `usk-mcp`, `usk-xlsx`, `usk-xml`,
  `usk-zip`, `ehkatra-io`, `ehkatra-mcp`, `usk_state::image`, the conformance
  harness, and this file. Four of §1's rows therefore describe code that passes
  323 tests and does not survive a fresh clone. The repository also has no
  pushed history, so the `supply-chain` job's first green is still owed. Neither
  half is a code defect; both are things a definition of done cannot assume.
* **TD-06 — auth is a bearer token.** Must not leak past the Q3 server plane.
* **TD-17 — recalc is single-threaded.** A-003's "on 8 cores" is unvalidated;
  the single-threaded path already beats the budget, so this is deliberate.

## 7. What this audit changed

An audit that finds nothing has usually not looked. This one found three things:

1. **`eval_top` re-evaluated its operands**, doubling the work of every
   top-level `+`/`-` formula: W-CHAIN-100K 92.6 → 145.2 ms. Fixed to 114.0 ms.
   Only the bench could see it; all 316 tests then in the suite passed throughout.
2. **W-OPEN-1M measured a container the product can no longer produce** — one
   snapshot and a bare tail, the shape TD-30 removed. Rebuilt to the real
   retention chain, which is how `lost_data = false` at 1M cells came to be
   measured at all.
3. **The snapshot-coverage test was a `BTreeSet` of a million op ids**, ~0.9 s
   of every cold open. Now a `HashSet`.

### 7b. What re-verifying this document changed

The audit above was itself re-run against the tree. The gates hold — 323 tests,
`fmt`, `clippy -D warnings`, dep budget 1/5 · 10/12 · 29/40, purity greps, and
W-REPLAY-5K bit-identical native and wasm32 at `c79fa533…` / `b58d5505…`. Four
things about the *document* did not hold:

1. **The test count was stale** — 316 in §2 against 323 in the tree.
2. **`tools/gates.ps1` is not runnable on a PowerShell 5.1 host** (TD-47). The

3. **§3 said "three of these moved" and named two.** W-ORACLE was the missing

   exists to catch in itself.
4. **The uncommitted working tree was not mentioned anywhere**, and it is the
   largest single qualification on §1. Now in §6 under TD-28 and in §8.
5. **The debt count was wrong** — 36 live against a mechanical count of 37 at

One inconsistency outside this file, left for its owner: **docs/44's TD-28 row
still describes the SQLite build blocker**, which D-073 unblocked in session 11,
while PROGRESS and this document both use TD-28 to mean "CI has never run". The
register row is stale and the ID now carries two meanings.

## 8. Status

**v0.1 is functionally complete against BOOTSTRAP's definition of done — every
row is built and proven by a named test, bench or workload — with one class of
exception outstanding, all of it version control, all of it the owner's to
close:**

1. **Rows 12–15 are not committed.** 45 paths in the working tree are
   uncommitted and the crates behind CSV, XLSX, MCP and the tile image are
   untracked (§6, TD-28). The code passes 323 tests; it is not yet in the
   repository's history.
2. **The repository has never been pushed**, so CI has never run and the
   `supply-chain` job's first green is still owed.
3. **`v0.1.0` is not tagged.**

BOOTSTRAP's definition of done asks for "repo pushed with tagged release
`v0.1.0`". Until (1) is closed, "proven" in §1 means *proven in this working
tree* — a distinction that costs nothing to state and everything to discover
later.

Committing, pushing and tagging are version-control actions and are deliberately
not taken here.
