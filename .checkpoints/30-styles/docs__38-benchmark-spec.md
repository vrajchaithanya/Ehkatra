# 38 — Benchmark Specification
Status: Approved · Normative: yes · Budgets live in docs/31 (single source); this doc specifies the *workloads* so numbers are reproducible and comparable across sessions and years

## Rules
Seeded generation only (LCG, fixed seeds committed) — a benchmark that can't reproduce its own workload measures nothing. Report: min of 5 runs for latency micro-benches; p50/p95 of 100 iterations for operation benches; RSS via OS-reported peak for memory. Machine context recorded with every number (CPU model, core count, target, opt level). Numbers land in MEASUREMENTS.md with the workload id — a number without a workload id is invalid.

## Workloads (id → definition)
**W-CHAIN-100K** (A-003, implemented Row 7): 10,000 rows × 10 columns; col A input values; cols B..K each `=prev_col + rand_const`, filled down — 100,000 formula cells in 10 chained groups. Measures: full recalc; single-edit incremental (edit one A cell, expected ~10 dirty cells). *Current: 53.0 ms full / 0.191 ms incremental, single-thread.*

**W-REPLAY-5K** (DP-A2 gate, implemented): the replay-check corpus — 5,000 seeded ops, 3 actors, mixed structural/cell. Measures: hash equality (pass/fail) + replay wall time.

**W-WIDE-AGG** (Row 7 follow-up): 100,000 rows × 5 data cols + one `SUM` per column + a grand total — the aggregation shape (few groups, huge ranges). Measures: full recalc; incremental after single data edit (expected: one partial-sum path, not 100k cells).

**W-TILE-10M** (A-001/A-002, due at TD-09 closure): 10M numeric cells written by 1 actor (import pattern), then 3-actor concurrent edit storm at 1% cell overlap (collab pattern), then 50% overlap (adversarial). Measures: RSS at load; bytes/cell; **promotion rate** per pattern; compaction ratio. *A-002 pass bar (restated per D-062, 2026-08-08): **promotion amplification ≤ 1.5× the contested-cell rate** (promoted cells ÷ contested cells ≤ 1.5 — correctness requires ≥ 1.0, since a contested cell must carry metadata per ADR-006; the original "<1% promotion at collab" was unattainable as written because the collab pattern contests exactly 1% by definition), **and** collab-pattern RSS ≤ 400 MB (the A-001 bar). Adversarial pattern (50% contested): no RSS bar — 50% genuinely contested cells legitimately cost memory; measured and recorded, revisit only if real-world telemetry ever shows contested rates above 5%.* Measured at TD-09 closure: amplification 1.0× (floor), collab RSS 123.6 MB — **pass**.

**W-SPARSE-SCATTER**: 1M cells scattered uniformly over a 10⁶×10³ identity space (0.1% density). Measures: RSS (sparse storage honesty — tiles must not materialize emptiness); point-read latency.

**W-STRUCT-STORM** (CRDT stress): 10,000 alternating row inserts/deletes from 3 actors at random anchors, 200 arrival orders. Measures: convergence (pass/fail); order-resolution wall time; tombstone count before/after compaction.

**W-EDIT-LATENCY** (A-004, Q2): scripted keystroke stream into a 10k-cell sheet with live recalc + (when shell exists) paint. Measures: keystroke→state p95; keystroke→paint p95.

**W-SYNC-RELAY** (Row 10, implemented `tools/sync-bench`): 2 and 50 replicas through one relay, each replica 10 ops/s for 60 s, 1% simulated packet loss. Measures: propagation p95; convergence time after last op; queued-op durability across a mid-run kill. Propagation and convergence are reported in **bus milliseconds** (the deterministic transport's simulated clock, one hop = 5 ms) because they are protocol properties — round trips to reach every replica — not properties of the host; wall time is reported separately. *Measured at Row 10 closure. 2 replicas: propagation p50 200 / p95 1,600 bus-ms; convergence 10 bus-ms; all replicas hash-equal; **32 ops queued at a mid-run kill, 32 delivered after recovery**; 0 quarantined; 97 ms wall. 50 replicas: 30,000 ops, 4,558 dropped frames / 2,085 reconnects, propagation p50 800 / p95 3,700 bus-ms, convergence 2,140 bus-ms, **all replicas hash-equal**, **45 ops queued at a mid-run kill and 45 delivered after recovery**, 6.8 min wall (120 min before TD-24 was paid — D-071/D-072).*
*The workload earned its place immediately: it found three convergence defects the whole test suite missed (D-067; the D-064 teardown branch, without which the 50-replica run diverged outright) plus a hollow durability row of its own. **Two harness notes worth keeping.** "Offline" must be a real partition, not a dropped frame plus a long timer — the latter lets the victim reconnect and drain before the kill, which made the durability row read 2 ops instead of 45 while looking like a result. And propagation must be counted at first delivery, not by scanning the receiver's log: an op held in the causal-gap buffer is counted twice by the latter, inflating the tail. See MEASUREMENTS.md and PROGRESS.md session 10.*

**W-OPEN-1M** (Row 11): container with 1M-cell workbook + 100k-op tail. Measures: cold open to READY (snapshot decode + replay); SALVAGE path time with a corrupted final page.

**W-ORACLE** (docs/32, ADR-024, implemented `tools/conformance`): every case in `tools/oracle-capture/vectors/` (1900 date system) and `vectors-1904/`, evaluated through `usk-formula` under `Profile::Compat` and compared against what Excel actually did. Measures: **the published Excel-compatibility percentage**, plus per-function pass rates and the full divergence list. This is not a latency workload; it earns a W-id for the same reason the others do — docs/38's rule is that a number without a workload id is invalid, and docs/32 makes this number a *product* attribute.
*Comparison rules (these are the workload; changing them changes the number):* numbers compared as `f64` against the **`number_r17` string** field, exactly — the JSON `number` field is not trustworthy through every parser (docs/50 §Corpus format) — with a separate `near` bucket (relative difference ≤ 1e-12) counted as a **fail** and reported alongside, so "the last bits differ" (TD-15) never quietly becomes a pass. Text and logicals compared exactly. Errors compared by canonical name, so `#VALUE!` where Excel says `#NUM!` is a fail. Cases Excel's own parser *rejected* pass only if ours rejects them too (D-081). Volatiles are the corpus's structural invariants (`=TODAY()=INT(NOW())`) evaluated against injected values, never a clock. `general_text` — Excel's value→text coercion, where `compat_round_15` lives — is **not** asserted, so the headline is *value* conformance and not display conformance; that omission is part of the number and is stated with it.
*Corpus provenance is part of the workload:* Excel 16.0 build 20228 (Microsoft 365), calc engine 191029, Windows 11 26200, `.` decimal / `,` list separator. One build, one locale. A second build is a second data point, not a re-run.
*Measured at the first run (session 12, 2026-08-08): **74.2%** — 1,014 of 1,366. Baseline before the same session's fixes was **65.6%**.*

## Regression policy for W-ORACLE specifically
The percentage may not fall between releases. A change that lowers it is a compatibility regression regardless of how correct it looks in isolation — that is the entire point of measuring against the binary rather than the documentation. A *deliberate* divergence (`Profile::Strict` behaviour, or a case where Excel is judged wrong to follow) is recorded as such in docs/44 with its vector id, and the runner counts it as a fail anyway: the number stays honest and the register carries the argument.

**W-IMAGE-STAMPS** (TD-46, implemented `tools/image-bench`): the W-TILE-10M patterns, measuring what a **stamp-carrying tile image** costs — resident state bytes/cell, image bytes/cell, and the per-cell size of a per-cell winner stamp under three encodings (naive in-memory layout; per-tile writer index plus `u64` lamport/counter; writer index plus delta-varint). Exists because `usk_state::image` cannot become `snapshots.body` until a summary tile can carry the stamps ADR-006 needs to retain a loser (D-101), and per-cell metadata is exactly what ADR-005 exists to avoid — so the encoding has to be measured against **A-001's 400 MB collab-pattern bar** rather than chosen.
*Measured 2026-08-09 at 1M and 2M cells, projected to 10M: naive **32 B/cell** → 428.8 MB total, **fails**; writer index + `u64`s **17 B/cell** → 285.7 MB, passes; **delta-varint 3.1 B/cell** → 153.2 MB, passes with 2.6x headroom. Per-cell figures are scale-stable (collab 3.10 → 3.12 B/cell from 1M to 2M); the adversarial pattern drifts (7.95 → 9.00) because a 50%-contested history deltas badly, and has no RSS bar. The measurement counts every cell, so it is an **upper bound**: a promoted cell already carries its stamp in `Meta::Mixed` and needs no sidecar entry.*

**W-XLSX-WRITE** (session 29, implemented `crates/usk-xlsx/tests/roundtrip.rs` — `the_write_fidelity_report`, run `--release -- --nocapture` to regenerate): every file in the reader's 20-file corpus, read → written by `usk_xlsx::write` → re-read through the same sandboxed reader. Measures: **the published write-fidelity percentage** — cells identical ÷ cells compared over the modelled surface (address, value, formula text, resolved number-format code; sheet names compared separately) — plus corpus write and re-read wall time, and output/input size ratio (stored entries, D-121). Losses and dropped parts are named per file by `WriteReport`, and the count of both is part of the published table, not a footnote.
*Comparison rules (these are the workload):* values by `Value` equality — numbers as the f64 the canonical rendering parses back to, so bit-value not display; formula text exact; number-format code exact; a cell missing or appearing is a non-identical cell. The synthetic half of the suite (in-engine workbook: stress doubles, every representable error, both format levels, sparse addresses, multi-sheet) asserts **100%** rather than measuring it — any loss on our own output is a defect. Excel is the external oracle: written files are opened in real Excel via COM (Excel 16.0, lifecycle rules per `tools/oracle-capture`) and cells read back; a written file Excel refuses is a writer defect regardless of our own reader's opinion, which is how the `#SPILL!` vocabulary gap was found (D-123).
*Measured session 29 (M1, release): **100.0%** — 49/49 modelled cells across all 20 files; 20/20 written files open in real Excel, 21/21 COM cell checks; output 2.06× input (stored entries, TD-72); corpus write 524–885 µs, re-read 762–1,646 µs over 3 runs.*

## Regression policy (docs/31)
Any budget breach blocks release. >5% p95 regression on any W-* workload vs the last release requires a signed-off debt entry. New feature areas must add a W-* entry here *before* their perf claims are stated anywhere — the workload spec is the license to publish a number.
